# songloft 接入清单（与 MiGPT 共存）

> 目标：同一台小爱音箱，既能陪聊（MiGPT），又能放歌（songloft + miot 插件）。
> 两边各自轮询小爱的**只读**对话日志，互不抢消息，靠关键词分工。
> 本文只写「配置」，不需要改任何一方的代码。

---

## 架构

| 角色 | 负责 | 关键词来源 |
| --- | --- | --- |
| **MiGPT**（本仓库，容器 `mi-gpt`，端口 8090） | 聊天、唤醒、换音色 | 前缀匹配 `startsWith` |
| **songloft + miot 插件**（容器 `songloft`，端口 58091） | 放歌、歌单、音量、定时 | 包含匹配 `includes` |

> ⚠️ **两边匹配方式不同**：MiGPT 是**前缀**（消息以关键词开头才命中），
> songloft 是**包含**（消息里出现关键词就命中）。所以 songloft 的关键词要挑得更谨慎。

数据流：

```
小爱音箱 ──► 小米云端对话日志（只读）
                  ├──► MiGPT 轮询（自己的游标）
                  └──► miot 插件轮询（自己的游标）
```

---

## 一、起 songloft 容器

`docker-compose.yml` 里已经加好了 `songloft` 服务（和 `mi-gpt` 同一个文件、各自独立容器）。
宿主机上执行：

```bash
docker compose pull
docker compose up -d
docker compose logs -f songloft
```

> **为什么不做成同一个镜像？** 端口天生错开、升级节奏差太远（合并会废掉 songloft 自带的
> `/api/v1/upgrade` 自升级）、它不只服务音箱、插件是运行时上传的、故障要隔离。

---

## 二、初始化 songloft

1. 浏览器打开 `http://<宿主机IP>:58091`
2. 用 compose 里填的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录
3. 把音乐文件放进 `./songloft/music`（宿主机路径），在界面里触发扫描
   - 曲库为空也能用，miot 插件支持「外部搜索源」把在线歌推给音箱

---

## 三、安装 miot 插件

下载最新版插件包：

```bash
wget https://github.com/songloft-org/songloft-plugin-miot/releases/latest/download/miot.jsplugin.zip
```

然后：**songloft 客户端 → 插件管理 → 上传 `.jsplugin.zip` → 启用**。

> 插件由作者独立仓库分发，songloft 主仓库不预置任何第三方插件。

---

## 四、插件配置（这几项是必填，漏一个都不工作）

进 **插件页 → 设置**：

| 配置项 | 默认值 | 要改成 | 说明 |
| --- | --- | --- | --- |
| `server_host` | 空 | `http://<宿主机局域网IP>:58091` | ⚠️ **最容易踩的坑**，见下方说明 |
| `conversation_monitor_enabled` | **`false`** | `true` | 不开就不轮询小爱对话，语音口令全部失效 |
| `voice_command_enabled` | **`false`** | `true` | 不开就不认语音口令 |
| 小米账号 `account` | — | 你的小米账号 | 平台账号（用户名/邮箱/手机） |
| `pass_token` | — | 你的 passToken | 见下方说明，能免验证码 |
| `timezone` | `Asia/Shanghai` | 一般不用动 | 定时任务用 |

### ⚠️ `server_host` 必须是「音箱能访问到的地址」

放歌走的是局域网 ubus —— **音频由音箱自己去拉流，不经过服务器**。
所以这里要填**宿主机的局域网 IP**（形如 `http://192.168.1.100:58091`），
填 `127.0.0.1`、`localhost` 或容器名，音箱都拉不到流，表现为「指令成功但没声音」。

> 源码注释原文：*「设置播放 URL 基础地址（如 `http://192.168.x.x:58091`）」*
> 且这是「给**音箱**访问用的局域网/公网地址」，插件自己发请求会另走本机 API 地址。

### passToken 从哪来

和 MiGPT 用的是同一套（本项目 `bbdd776` 提交已支持）。
在浏览器 F12 → Application → Cookies → `passToken`，复制值填进 `pass_token`。
带上它小米会直接放行，**不会再下发验证码**，也就不会撞 `70022 验证码发送过多`。

## 五、MiGPT 侧配置

打开 `http://<宿主机IP>:8090` 的配置页，改**三个关键词列表**：

| 配置项 | 现在的值 | 改成 | 原因 |
| --- | --- | --- | --- |
| `callAIKeywords` | `请` `你` | `傻妞` | `请`/`你` 太宽泛，会跟 songloft 的「播放…」抢指令 |
| `exitKeywords` | `关闭` `退出` `再见` | `退出对话` `结束对话` `再见` | `关闭` 和 songloft 的 stop 关键词重叠 |
| `wakeUpKeywords` | `召唤` | 不用动 | songloft 不占这个词 |

## 六、关键词冲突对照表

songloft 默认语音口令（节选，可在插件设置页逐条增删）：

| songloft 指令 | 默认关键词 |
| --- | --- |
| 播放歌单 | 播放歌单 / 放歌单 / 播放列表 |
| 播放歌曲 | 播放歌曲 / 放歌曲 / **我想听** |
| 下一首 | 下一首 / 切歌 / 换一首 / 下一曲 |
| 停止 | 暂停播放 / 停止播放 / 暂停音乐 / 停一下 / pause / stop / 停止 / 别播了 / 关掉音乐 / **关机** / **关闭** / 暂停 |
| 音量 | 设置音量 / 音量调到 / 音量 / 声音 / 大声一点 / 小声一点 |

对照本项目：

| 冲突 | 严重度 | 处理 |
| --- | --- | --- |
| MiGPT `请` ↔ songloft「请**播放歌单**」 | 🔴 高 | 把 `callAIKeywords` 收窄成 `傻妞` |
| MiGPT `你` ↔ songloft 各类口令 | 🟡 中 | 同上 |
| MiGPT `关闭` ↔ songloft `关闭` | 🟢 低 | 两边都是「停」，结果一致；改掉更干净 |
| songloft `关机` / `关闭` 太宽泛 | 🟡 中 | 建议在**插件设置页**把 `关机`、`关闭` 从 stop 列表里删掉，否则「关闭空调」也会停歌 |

> 匹配方式差异提醒：songloft 是**包含**匹配，所以它列的关键词越短越危险。

## 七、验证

按顺序测，每步都能单独定位问题：

1. **只测聊天**：对小爱说「傻妞，你好」→ 应该有 AI 回复
2. **只测放歌**：对小爱说「播放歌单」→ 应该开始放歌（此时先别说「傻妞」）
3. **测共存**：放着歌说「傻妞，现在几点」→ AI 回答，**歌不应该被永久掐断**
   （这是本项目 `85b5cba` 提交修的行为：聊天指令不再无条件 `pause()`）
4. **测退出**：说「退出对话」→ 傻妞退出，歌曲不受影响

## 八、排错

| 现象 | 原因 |
| --- | --- |
| 指令识别成功但没声音 | `server_host` 不是局域网可达地址 |
| 完全不理语音口令 | 插件里 `conversation_monitor_enabled` / `voice_command_enabled` 还是 `false` |
| 说「关闭」音乐停了但傻妞也退出了 | `exitKeywords` 里的 `关闭` 还没删 |
| 说「请播放…」傻妞答非所问 | `callAIKeywords` 里的 `请` 还没删 |
| 触发验证码 / `70022` | `pass_token` 没填，或填的已失效 |
| 音箱型号放不出某些歌 | 开插件里的 `force_mp3`（部分机型不支持 flac/aac） |
